## When Adding New Content

### Creating a New Wiki Page

1. **Identify the correct location:** Determine the appropriate directory for your new page (e.g., `biblical/`, `neuroscience/`, `philosophy/`).
2. **Analyze existing content:** Before writing, review several existing pages within the same category. Pay close attention to:
    - **Style:** Observe the writing tone (e.g., scholarly but accessible, non-dogmatic).
    - **Content-Length:** Get a feel for the typical length of pages in the section.
    - **Structure:** Note the use of headings, front matter, lists, blockquotes, and other markdown conventions.
    - **Citations:** Understand how sources are cited (e.g., links to primary sources, DOI links for research).
3. **Create the new file:** Create a new `.md` file with a descriptive name (e.g., `new-concept.md`).
4. **Add Front Matter:** Start with the necessary YAML front matter. For most pages, this is just the title. Titles with colons (`:`) MUST be quoted.

    ```yaml
    ---
    title: "Your New Page Title: With a Subtitle"
    ---
    ```

5. **Write Content:** Following the conventions you observed, write the content for your page.
6. **Verify:** Reread your page to ensure it is consistent with the project's standards. After adding a new page, the sidebar will need to be regenerated, which is typically handled by scripts in the `.vitepress` directory.

## Testing & Validation

**CRITICAL**: Every time you finish modifying or creating markdown files, you MUST execute a markdown lint to ensure compliance with the project's standards.

1. **Check markdown lint**: Execute `npx -y markdownlint-cli <file_path>` (or the appropriate linting command) and ensure blank lines around headings/lists and other rules in `.markdownlint.json` are followed.
2. **Verify links with lychee**: Execute `lychee <file_path>` to ensure all links (internal and external) are valid.
3. **Verify links (manual)**: All internal links should resolve.
4. **Cite sources**: Philosophy and neuroscience claims need citations.
5. **Test locally**:

   ```bash
   npm run docs:dev
   ```

6. **Check collection rendering**: Ensure new pages appear correctly in the navigation.
